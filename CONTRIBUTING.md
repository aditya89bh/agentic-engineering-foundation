# Contributing

Contributions should keep the course approachable, framework-independent, and grounded in software engineering.

## Workflow

1. Create a focused branch.
2. Keep changes within the relevant day or shared setup material.
3. Run all Python examples you change.
4. Check links and Markdown rendering.
5. Open a pull request explaining the learning goal, verification, and limitations.

## Content guidelines

- Prefer explicit state and control flow over hidden abstractions.
- Introduce dependencies only when they teach a required concept.
- Keep starter code approachable and solutions readable.
- Include failure behavior and verification steps.
- Do not commit API keys, credentials, student data, or generated secrets.
